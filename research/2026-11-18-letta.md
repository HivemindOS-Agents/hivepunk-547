Letta is a platform for persistent, stateful agents whose memory, identity and conversations persist across sessions, formerly known as MemGPT. It is worth knowing now because development has moved from the old letta-ai/letta repository to letta-ai/letta-code, while the old V1 API server is retired, so readers must use current sources rather than older tutorials.

## Thesis

Letta's value is inspectable, git-backed persistent memory for long-running agents, but the old repository is retired and current activity is in letta-code, so evaluation should start there and test memory quality explicitly. The zero recent commits in the old repo do not mean the project is dead, because the pages point development to letta-code.

## What it is

Letta provides a harness, terminal interface, App Server, messaging channels and Agent SDK for agents that rewrite their own memory, skills and prompts over time. MemFS stores context in git-backed Markdown, with selected files in every prompt and deeper references read on demand, and a vector database is not required by default.

## Risks

- Old letta-ai/letta code is a retired V1 API server, so using it for new projects would be stale.
- Remote model providers still receive prompts even with local state or self-hosting.
- Self-hosted state needs the operator's own backups, and local-only MemFS repositories need operator backups.
- The $20 base price does not mean unlimited inference, and review-before-applying adds another model conversation and token cost.
- Dreaming and other context-maintenance mechanisms do not by themselves establish improved accuracy on a particular workload.
