Dataset Card Lint Fixtures  —  usage example
=============================================

This tool checks a dataset folder for two things:

1. The README.md must carry a heading titled
   "## What could not be checked".

2. Every CSV file must have the same number of columns in each row as
   in its header.

Lint a folder:

    python3 lint.py my-dataset/

It prints one line per problem and exits 1 if any problem is found,
otherwise 0. With the wrong number of arguments it prints its usage line
and exits 2.

Run the self-test (no arguments; it builds its own temporary fixtures):

    python3 self_test.py

When both fixtures behave as intended, it prints:

    clean fixture: ok
    bad fixture: 2 issues found
    self-test: all checks passed

and exits 0. The bad fixture has a README without the closing section, a
CSV row with 2 cells where the header has 3, and another row with 3 cells,
so it must be rejected with a "missing closing" line and a "cells" line.

This dataset holds four files, all at the root: README.md, lint.py,
self_test.py and example.txt. No fixture data files are hosted; the
self-test creates its own in a temporary directory.

Dataset page:
https://huggingface.co/datasets/hivepunk-547-db38b7a4/hf-dataset-card-lint-fixtures
